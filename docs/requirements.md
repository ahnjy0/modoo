# MODOO 커뮤니티 앱 요구사항 정의서

## 0. 개요

- **제품명**: MODOO — "모두의 디자인 커뮤니티"
- **형태**: 모바일 웹 커뮤니티 앱 (React + TypeScript + Tailwind CSS, 모바일 뷰포트 기준 SPA)
- **현재 상태**: 프론트엔드 프로토타입. 실제 백엔드/인증/DB 연동 없이 로컬 state와 목(mock) 데이터로 동작.
- **핵심 가치**: 사용자가 일상, 정보, 취미 등 다양한 주제의 글을 작성/공유하고, 좋아요·댓글·북마크·팔로우로 상호작용하는 커뮤니티 서비스.

## 2. 기능별 상세 요구사항

### 2.1 회원가입 (SignUpView)
- 입력 항목: 프로필 사진(선택), 닉네임(필수, 중복확인 버튼 제공), 이메일(필수, 인증번호 전송 버튼 제공), 비밀번호(필수), 비밀번호 확인(필수)
- 비밀번호와 비밀번호 확인이 일치하면 즉시 확인 메시지 표시
- 약관 동의: 전체 동의 체크박스, [필수] 서비스 이용약관, [필수] 개인정보 수집·이용, [선택] 마케팅 정보 수신
- 필수 약관(서비스 이용약관, 개인정보 수집) 미동의 시 가입 제출 차단 및 안내 메시지 표시
- 가입 완료 시 환영 메시지 표시 후 피드 화면으로 이동
- 로그인 화면으로 돌아가는 링크 제공

### 2.2 로그인 (LoginView)
- 입력 항목: 이메일(필수), 비밀번호(필수, 표시/숨김 토글 가능)
- "로그인 상태 유지" 체크박스 제공(기본 활성화)
- "비밀번호 찾기" 클릭 시 재설정 이메일 발송 안내
- 이메일 미입력 시 로그인 차단 및 안내
- 소셜 로그인(카카오, 구글) 버튼 제공 — 클릭 시 일반 로그인과 동일하게 처리
- 로그인 성공 시 완료 알림 후 피드 화면으로 이동
- 회원가입 화면으로 이동하는 링크 제공

### 2.3 피드 / 홈 (FeedView)
- 카테고리 칩(전체/일상/정보공유/질문·답변/취미·모임/라이프)으로 게시글 필터링
- 게시글 카드에 표시되는 정보: 작성자(아바타, 이름, 뱃지, 온라인 표시), 작성 시각, 제목, 본문 요약(2줄 말줄임), 대표 이미지(있는 경우, 여러 장이면 장수 표시), 링크 프리뷰(있는 경우), 해시태그, 좋아요 수, 댓글 수, 좋아요/댓글/북마크/공유 액션
- 게시글 카드 클릭 시 상세 화면으로 이동
- 작성자 영역 클릭 시 해당 사용자 프로필로 이동
- 우측 하단 플로팅 버튼(FAB)으로 글쓰기 화면 진입
- 공유 버튼 클릭 시 클립보드 복사 및 2초간 완료 아이콘 표시
- 더보기(⋮) 클릭 시 신고/차단 메뉴 노출(현재는 알림으로 대체 표시)

### 2.4 게시글 작성 (PostCreateView)
- 카테고리 선택(일상/정보공유/질문·답변/취미·모임) — 필수, 기본값 "일상"
- 제목 입력(필수)
- 본문 입력(필수, 최대 2000자, 실시간 글자 수 카운터 표시)
- 해시태그: 자유 입력 후 추가, `#` 접두사 자동 부여, 중복 태그 방지, 개별 삭제 가능
- 이미지: 최대 5장 첨부, 첫 번째 이미지가 "대표" 이미지로 표시, 개별 삭제 가능, 5장 초과 시 경고 알림
- 제목 또는 본문이 비어있으면 등록 차단 및 안내 메시지
- "임시저장" 버튼 제공(현재는 알림으로 저장 완료 안내만 표시)
- "등록" 시 새 게시글이 피드 최상단에 추가되고, 해당 게시글 상세 화면으로 자동 이동
- 위치 태그, 이모지 삽입 등 보조 입력 기능 제공(하단 툴바)

### 2.5 게시글 상세 (PostDetailView)
- 작성자 정보(아바타, 이름, 인증 배지, 작성 시각, 조회수), 팔로우 버튼
- 카테고리 태그, 제목, 본문, 이미지 갤러리(대표 이미지 + 서브 이미지 그리드), 해시태그 목록
- 좋아요/댓글 수 및 좋아요·북마크·공유 액션 바
- 댓글 목록: 작성자, 작성 시각, 내용, 좋아요 수, 답글 달기 버튼
- 대댓글(답글): 들여쓰기된 영역에 표시, 게시글 작성자의 답글에는 "작성자" 배지 표시
- 화면 하단 고정 댓글 입력창: 텍스트 입력 후 전송, 빈 값이면 전송 버튼 비활성화
- 댓글 등록 시 목록 최상단에 추가되고 게시글의 댓글 수 즉시 갱신
- 뒤로가기 버튼으로 이전 화면 복귀

### 2.6 좋아요 / 북마크
- 좋아요 토글 시 좋아요 수 증감 및 아이콘 색상(빨강) 변경, 피드·상세 화면 상태 동기화
- 북마크 토글 시 아이콘 색상(보라/파랑 계열) 변경, 별도의 "스크랩" 목록으로 취급(사용자 프로필의 "스크랩한 글" 탭과 연계되는 개념)

### 2.7 검색 (SearchView)
- 검색창에 키워드 입력, 검색 버튼 클릭 시 최근 검색어 목록에 추가(중복 제외)
- 최근 검색어: 개별 삭제, 전체 삭제 가능, 클릭 시 검색어로 재입력
- 인기 급상승 키워드 목록(순위, 키워드, 상승/유지 표시) 제공, 클릭 시 검색어로 반영
- 결과 탭: 전체 / 게시글 / 사용자 (각 탭에 결과 수 배지 표시)
- 사용자 검색 결과: 아바타, 이름, 핸들, 작성글 수, 팔로워 수, 소개, 팔로우 버튼
- 게시글 검색 결과: 작성자, 작성 시각, 검색어 하이라이트가 포함된 제목, 본문 요약, 썸네일, 좋아요/댓글/조회수, 북마크 버튼
- 게시글 결과 클릭 시 게시글 상세로 이동

### 2.8 내 프로필 / 내 피드 (MyProfileView)
- 상단에 작성 글 수 배지, 글쓰기 바로가기, 공유, 설정 진입 버튼
- 프로필 요약 카드: 아바타(클릭 시 프로필 수정 이동), 이름, 인증 배지, 뱃지 타이틀, 핸들, 활동 레벨
- 통계: 내가 쓴 글 수, 받은 좋아요 합계, 총 댓글 수 (실제 보유 게시글 데이터 기반 자동 집계)
- 카테고리 필터(내가 쓴 글의 카테고리 기준 동적 생성) 및 정렬(최신순/좋아요순) 제공
- 게시글 없음 상태: 안내 메시지와 "첫 피드 작성하기" 버튼 표시
- 각 게시글 카드에 카테고리, 작성 시각, 제목, 본문 요약, 팁(있는 경우), 썸네일, 태그, 좋아요/댓글/조회수, 북마크 표시
- 게시글 카드의 더보기(⋮) 메뉴: 링크 복사, 글 삭제
- 글 삭제 시 확인 팝업 → 확인 시 목록에서 제거 및 완료 토스트 표시(상세 화면에서 삭제 시 이전 화면으로 복귀)
- 액션 완료 시 화면 상단에 토스트 메시지로 피드백 제공

### 2.9 다른 사용자 프로필 (UserProfileView)
- 아바타, 인증 배지, 지식 레벨 배지, 이름, 핸들, 소개글
- 통계: 작성한 글, 받은 좋아요, 팔로워 수(팔로우 시 +1 즉시 반영)
- 팔로우/팔로잉 토글 버튼, 커피챗(1:1 메시지) 신청 버튼
- 탭: 작성한 글 / 스크랩한 글 (탭별 게시글 수 배지)
- 게시글 목록: 카테고리, 작성 시각, 제목, 본문 요약, 이미지 또는 링크형 콘텐츠 카드, 좋아요/댓글 수, 북마크 토글
- 게시글 클릭 시 상세 화면으로 이동
- 공유 버튼(프로필 링크 복사), 차단/신고 메뉴

### 2.10 프로필 수정 (EditProfileView)
- 프로필 사진: 파일 업로드(이미지 파일만 허용, 5MB 이하), 드래그 앤 드롭 지원, 프리셋 아바타 선택, 기본값 복원
- 닉네임(필수, 2자 이상, 최대 20자, 실시간 글자 수 표시)
- 아이디/핸들(필수, `@` 접두사 자동 부여, 최대 30자)
- 프로필 뱃지/전문 타이틀(최대 25자)
- 한 줄 소개(최대 150자, 실시간 글자 수 표시)
- 웹사이트/SNS 링크
- 저장 시 유효성 검증(닉네임 최소 길이) 실패하면 토스트로 안내
- 저장 성공 시 현재 사용자 정보 및 해당 사용자가 작성한 모든 게시글의 작성자 정보(이름/핸들/아바타/뱃지)가 함께 갱신됨
- 저장 또는 취소 시 이전 화면(설정 등)으로 복귀

### 2.11 알림 (NotificationsView)
- 알림 유형: 좋아요, 댓글, 팔로우, 시스템 공지, 언급(mention)
- 필터 탭: 전체 / 활동(좋아요·댓글·팔로우·언급) / 공지사항(시스템)
- 안 읽은 알림 수 배지 표시, "모두 읽음" 일괄 처리
- 개별 알림 삭제, 전체 삭제(확인 팝업 포함)
- 알림 클릭 시 읽음 처리되고, 연결된 게시글이 있으면 해당 게시글 상세로 이동
- 알림 없음 상태에 대한 안내 문구(필터별 다른 문구) 제공
- 보관 기간 안내 문구(최대 30일) 표시

### 2.12 설정 (SettingsView)
- 계정 및 개인화: 프로필 요약(클릭 시 프로필 수정), 프로필 수정 바로가기, 푸시 알림 on/off 토글, 화면 테마 선택(시스템 설정 따름/라이트/다크)
- 커뮤니티 및 콘텐츠 보호: 차단한 사용자 관리, 게시글·댓글 키워드 필터링
- 정보 및 고객지원: 공지사항(NEW 배지), 서비스 이용약관, 개인정보처리방침, 오픈소스 라이선스, 버전 정보
- 로그아웃: 확인 팝업 후 로그인 화면으로 이동
- 회원탈퇴: 확인 팝업 후 탈퇴 완료 알림 및 회원가입 화면으로 이동
- 앱 버전 정보 및 브랜드 푸터 표시

### 2.13 내비게이션 (Header / BottomNav)
- 상단 헤더: 홈 화면에서는 브랜드 로고 + 알림 벨(안읽음 표시) + 내 프로필 아바타, 하위 화면(상세/작성/사용자프로필/로그인/회원가입)에서는 뒤로가기 + 화면 제목
- 하단 탭바: 홈, 검색, 내 피드, 설정 4개 탭 (게시글 작성/로그인/회원가입 화면에서는 숨김)
- 화면 전환 시 스크롤 위치 최상단으로 자동 이동
- 뒤로가기는 직전 화면으로 복귀(상세, 작성, 사용자프로필, 로그인, 회원가입, 알림, 프로필수정 화면에서 동작)

## 3. 사용자 흐름

### 3.1 신규 사용자 온보딩
```
앱 진입(피드) → 로그인/회원가입 필요 시 로그인 화면 진입
  → "회원가입" 선택 → 닉네임/이메일/비밀번호 입력 → 약관 동의
  → 가입 완료 → 피드 화면 진입
```

### 3.2 로그인
```
로그인 화면 → 이메일/비밀번호 입력 (또는 소셜 로그인 버튼 클릭)
  → 로그인 성공 → 완료 알림 → 피드 화면 진입
```

### 3.3 게시글 작성 및 확인
```
피드 or 내 피드 화면 → 글쓰기(FAB 또는 버튼) → 게시글 작성 화면
  → 카테고리 선택 → 제목/본문 입력 → 태그 추가 → 이미지 첨부
  → 등록 → 게시글 상세 화면으로 자동 이동 (피드 최상단에도 반영)
```

### 3.4 게시글 열람 및 상호작용
```
피드 → 게시글 카드 클릭 → 게시글 상세
  → 좋아요/북마크 토글, 댓글 작성, 공유
  → 작성자 아바타 클릭 → 작성자 프로필로 이동
  → 뒤로가기 → 피드로 복귀
```

### 3.5 검색
```
검색 탭 진입 → 키워드 입력 또는 인기 키워드/최근 검색어 클릭
  → 결과 탭(전체/게시글/사용자) 확인
  → 게시글 클릭 시 상세로 이동 / 사용자 클릭 시 프로필로 이동 / 팔로우 토글
```

### 3.6 내 피드 관리
```
내 피드 탭 진입 → 통계 확인 → 카테고리 필터·정렬 적용
  → 게시글 클릭 시 상세로 이동
  → 더보기(⋮) → 링크 복사 또는 삭제(확인 후 반영)
  → 아바타/수정 버튼 클릭 → 프로필 수정 화면 이동
```

### 3.7 프로필 수정
```
설정 or 내 피드 → 프로필 수정 화면 진입
  → 사진 변경(업로드/드래그앤드롭/프리셋) → 닉네임/핸들/뱃지/소개/링크 입력
  → 저장 → 유효성 검증 통과 시 전역 사용자 정보 및 기존 게시글 작성자 정보 갱신
  → 이전 화면(설정 등)으로 복귀
```

### 3.8 알림 확인
```
피드 화면 벨 아이콘 클릭 → 알림 목록
  → 필터(전체/활동/공지) 선택
  → 알림 클릭 → 읽음 처리 + 연결된 게시글 있으면 상세로 이동
  → 모두 읽음 / 개별·전체 삭제
```

### 3.9 로그아웃 / 회원탈퇴
```
설정 화면 → 로그아웃 클릭 → 확인 팝업 → 로그인 화면으로 이동
설정 화면 → 회원탈퇴 클릭 → 확인 팝업 → 완료 알림 → 회원가입 화면으로 이동
```

## 5. 데이터 개요

현재는 `src/data/mockData.ts`의 목업 데이터와 `App.tsx`의 React state로만 관리되며, 별도의 백엔드/DB는 없음. 주요 데이터 모델(`src/types.ts` 기준)은 다음과 같음.

### 5.1 UserProfile (사용자 프로필)
| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 사용자 고유 ID |
| name | string | 닉네임 |
| handle | string | `@` 핸들 |
| avatar | string | 프로필 이미지 URL |
| badgeTitle | string? | 뱃지/전문 타이틀 |
| isCertified | boolean | 인증 회원 여부 |
| level | string | 활동 레벨 표시 문구 |
| bio | string | 한 줄 소개 |
| website | string? | 웹사이트/SNS 링크 |
| postCount | number | 작성 글 수 |
| likeCount | number | 받은 좋아요 수 |
| followerCount | number | 팔로워 수 |
| isFollowing | boolean? | (조회 대상 기준) 팔로우 여부 |

### 5.2 Post (게시글)
| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 게시글 고유 ID |
| author | Author | 작성자 요약 정보(id, name, handle, avatar, badge, isCertified, level) |
| createdAt | string | 작성 시각(표시용 문자열) |
| category | string | 카테고리 |
| title | string | 제목 |
| content | string | 본문 |
| images | string[] | 첨부 이미지 URL 목록(최대 5장) |
| tags | string[] | 해시태그 목록 |
| likes | number | 좋아요 수 |
| commentsCount | number | 댓글 수 |
| views | number | 조회수 |
| isLiked | boolean | 현재 사용자의 좋아요 여부 |
| isBookmarked | boolean | 현재 사용자의 북마크 여부 |
| linkPreview | LinkPreview? | 외부 링크 미리보기(title, url, status, ping) |
| tip | string? | 게시글 요약 팁 문구 |

### 5.3 Comment (댓글)
| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 댓글 고유 ID |
| postId | string | 소속 게시글 ID |
| author | { name, avatar, isAuthor? } | 댓글 작성자 정보(게시글 작성자 여부 포함) |
| createdAt | string | 작성 시각 |
| content | string | 댓글 내용 |
| likes | number | 좋아요 수 |
| isLiked | boolean? | 좋아요 여부 |
| replies | Comment[]? | 대댓글(답글) 목록 |

### 5.4 AppNotification (알림)
| 필드 | 타입 | 설명 |
|------|------|------|
| id | string | 알림 고유 ID |
| type | 'like' \| 'comment' \| 'follow' \| 'system' \| 'mention' | 알림 유형 |
| title | string | 알림 제목 |
| message | string | 알림 본문 |
| createdAt | string | 발생 시각 |
| isRead | boolean | 읽음 여부 |
| user | { name, avatar, handle? }? | 관련 사용자(시스템 알림은 없음) |
| postId | string? | 연결된 게시글 ID(있는 경우 클릭 시 이동) |

### 5.5 데이터 관계 요약
- 1명의 `UserProfile`(작성자)은 여러 개의 `Post`를 가질 수 있음 (1:N)
- 1개의 `Post`는 여러 개의 `Comment`를 가질 수 있음 (1:N), `Comment`는 다시 여러 개의 하위 `Comment`(답글, 1단계)를 가질 수 있음
- `AppNotification`은 선택적으로 하나의 `Post`(`postId`) 및 하나의 유저 요약 정보(`user`)를 참조함
- 현재 프로필 수정 시 동일 사용자가 작성한 모든 `Post.author` 정보가 함께 갱신되도록 연동되어 있어, 사실상 작성자 정보는 `UserProfile`을 참조하는 형태로 동작함(다만 스키마상으로는 각 Post에 author 스냅샷이 내장되어 있음)

### 5.6 한계 및 참고 사항
- 모든 데이터는 브라우저 세션 내 메모리 상태로만 유지되며, 새로고침 시 초기 목업 데이터로 리셋됨
- 로그인/회원가입은 실제 인증 처리 없이 UI 흐름만 구현됨(비밀번호 검증, 세션 토큰 등 없음)
- 검색 결과, 다른 사용자 프로필(예: 팔로워 수, 게시글 목록 일부)은 목업 고정값이 섞여 있어 실제 게시글 데이터와 완전히 연동되어 있지 않음
