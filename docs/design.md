# 피드(홈) 화면 디자인 분석

> 분석 대상: `FeedView` (`src/components/FeedView.tsx`) + 공통 레이아웃(`App.tsx`, `Header.tsx`, `BottomNav.tsx`)
> 현재 앱 실행 시 기본으로 표시되는 화면(`http://localhost:3000`)이며, 색/간격/타이포그래피 톤은 Tailwind CSS v4 기본 팔레트를 그대로 사용(별도 `tailwind.config` 커스텀 없음, `src/index.css`에서 `@import "tailwindcss"`만 선언). 따라서 여기서 정리한 톤은 다른 화면들에서도 동일하게 반복되는 앱 전역 디자인 시스템이다.

---

## 1. 화면 구조

전체 앱은 **모바일 디바이스 프레임을 흉내 낸 중앙 정렬 컨테이너** 구조이며, 그 안에서 Header - 본문(스크롤 영역) - BottomNav가 세로로 쌓이는 3단 레이아웃이다.

```
<body> (bg-slate-100)
└─ 루트 래퍼 (min-h-screen, flex justify-center)
   └─ 앱 컨테이너 (max-w-md, bg-white, shadow-xs, border-x)   ← 모바일 프레임
      ├─ Header (sticky top-0)                                ← 브랜드 로고 + 알림 + 내 아바타
      ├─ <main> (flex-1, overflow-y-auto)                      ← 스크롤 영역
      │   └─ FeedView
      │       ├─ 카테고리 칩 바 (sticky top-0, z-30)
      │       ├─ 게시글 카드 리스트 (space-y-3.5)
      │       │   └─ 게시글 카드 × N
      │       │       ├─ 작성자 헤더 (아바타/이름/뱃지/시간/더보기)
      │       │       ├─ 제목 + 본문 요약(2줄)
      │       │       ├─ (선택) 대표 이미지
      │       │       ├─ (선택) 링크 프리뷰 카드
      │       │       ├─ (선택) 해시태그 목록
      │       │       └─ 액션 바 (좋아요/댓글/북마크/공유)
      │       └─ FAB "글쓰기" 버튼 (fixed, bottom-20 right-6)
      └─ BottomNav (sticky bottom-0)                           ← 홈/검색/내피드/설정 4탭
```

### 레이아웃 특징
- **모바일 퍼스트 단일 컬럼**: 앱 컨테이너 `max-w-md`(448px)로 데스크톱 뷰포트에서도 모바일 폭을 유지하고, 좌우는 `border-x`로 카드처럼 분리되어 배경(`bg-slate-100`)과 대비를 준다.
- **콘텐츠 내부는 `max-w-lg`(512px)**: 리스트 영역은 컨테이너보다 살짝 넓은 제약을 두지만 실질적으로는 컨테이너 폭에 맞춰짐 — 폭 제한이 이중으로 걸려 있어 반응형 확장 여지를 열어둔 구조.
- **2단 sticky 헤더**: 최상단 브랜드 Header + 그 아래 카테고리 칩 바가 각각 `sticky top-0`으로 겹겹이 고정되어, 스크롤해도 "브랜드"와 "필터" 두 컨텍스트가 항상 노출됨.
- **FAB + 하단 탭바 이중 플로팅**: 글쓰기 FAB(`bottom-20`)가 BottomNav 바로 위에 떠 있어 서로 겹치지 않도록 여백이 계산되어 있음(FAB 아래 `pb-20` 여백을 리스트 컨테이너에 사전 확보).
- **배경 레이어 분리**: 화면 배경은 `bg-slate-50`(약한 회색), 카드/헤더는 `bg-white`로 올려 카드가 배경 위에 "떠 보이는" 대비를 만듦.

## 2. 주요 컴포넌트

| 컴포넌트 | 역할 | 핵심 스타일 특징 |
|---|---|---|
| **Header** | 브랜드 로고, 알림 벨(안읽음 뱃지), 내 프로필 진입 | `sticky`, `bg-white/95 backdrop-blur-md`, 로고는 `indigo-600` 정사각 배지 + 워드마크 |
| **카테고리 칩 바** | 전체/일상/정보공유/질문답변/취미모임/라이프 필터 | 가로 스크롤(`overflow-x-auto no-scrollbar`), pill 버튼, 선택 시 `bg-indigo-600` 채움 |
| **게시글 카드 (article)** | 피드의 핵심 단위, 클릭 시 상세 이동 | `rounded-2xl`, `border`, `shadow-sm`, hover 시 테두리 진해짐 + 이미지 미세 확대(`scale-102`) |
| ┗ 작성자 헤더 | 아바타(온라인 점), 이름, 뱃지 pill, 작성시간, 더보기(⋮) | 아바타 40px + 우하단 `emerald-500` 온라인 표시 점 |
| ┗ 제목/본문 | 제목(굵게) + 본문 2줄 말줄임 | `line-clamp-2`로 카드 높이 균일화 |
| ┗ 이미지 영역 | 대표 이미지 1장(다중일 때 장수 배지) | `aspect-[16/10]` 고정 비율, 우하단 `1 / N` 카운터(반투명 블랙 캡슐) |
| ┗ 링크 프리뷰 카드 | 외부 링크(배포 URL 등) 미리보기 | `indigo-50/70` 배경 + 아이콘 배지 + 상태 점(pulse 애니메이션) |
| ┗ 해시태그 | 게시글 태그 목록 | `bg-slate-100` 회색 pill, hover 시 진해짐 |
| ┗ 액션 바 | 좋아요/댓글/북마크/공유 | 아이콘+숫자, 활성 상태는 색+채움(fill)으로 표현, 상단 `border-t`로 본문과 구분 |
| **FAB (글쓰기 버튼)** | 새 글 작성 진입 | `fixed`, 원형+텍스트 결합형 pill, `shadow-lg shadow-indigo-300/50`으로 입체감 |
| **BottomNav** | 홈/검색/내 피드/설정 탭 전환 | 아이콘+라벨 세로 배치, 활성 탭은 `indigo-600` 색 + 하단 작은 점 인디케이터 |

### 컴포넌트 상태 표현 패턴
- **선택/비선택**: 카테고리 칩, 하단 탭 모두 "채움(indigo-600 배경 또는 텍스트 색)" vs "중립(slate)"의 이진 대비로 표현.
- **토글형 액션(좋아요/북마크)**: 기본은 outline 아이콘 + slate 계열, 활성화 시 해당 의미 색(좋아요=rose, 북마크=indigo)으로 색상과 `fill`을 동시에 바꿔 상태를 이중으로 강조.
- **일시적 피드백(공유 복사)**: 아이콘을 2초간 `Check`(emerald)로 스왑했다가 원래 아이콘으로 복귀 — 별도 토스트 없이 아이콘 자체가 피드백 역할.

## 3. 색 톤 (Color)

Tailwind 기본 팔레트를 커스터마이즈 없이 사용하며, 역할별로 명확하게 분리되어 있다.

| 역할 | 색상 | 사용처 |
|---|---|---|
| **브랜드/Primary** | `indigo-600` (핵심), `indigo-50`/`indigo-100` (연한 배경) | 로고, FAB, 활성 탭/칩, 프라이머리 버튼, 링크 프리뷰 배경, 선택된 뱃지 |
| **중립(Neutral) 배경** | `slate-50`(화면 배경) → `white`(카드/헤더) → `slate-100`(비활성 칩/태그) | 배경-표면 계층 구분의 기본 축 |
| **중립 텍스트** | `slate-900`(제목/강조), `slate-600`(본문), `slate-400`(메타/타임스탬프/placeholder) | 텍스트 위계 3단계 |
| **중립 경계선** | `slate-100`/`slate-200` | 카드 테두리, 구분선(`border-t`, `border-b`) |
| **의미색 - 좋아요/위험** | `rose-500` | 좋아요 활성 아이콘, 삭제/경고성 텍스트(다른 화면 기준) |
| **의미색 - 성공/온라인** | `emerald-500`/`emerald-600` | 온라인 표시 점, 공유 복사 완료 체크, 성공 토스트 |
| **의미색 - 정보/링크 상태** | `indigo` 계열(위와 동일 축) | 링크 프리뷰의 "Production Live" 상태 점(`emerald`)과 카드 배경(`indigo-50/70`)이 혼합 사용 |
| **오버레이** | `black/60` | 이미지 위 장수 카운터 배지(반투명 블랙 + `backdrop-blur-sm`) |
| **반투명 유리 효과** | `white/95` + `backdrop-blur-md` | 스티키 헤더/탭바(카드 위에 겹쳐도 아래 콘텐츠가 은은히 비쳐 "떠 있는" 느낌) |

**톤 요약**: 채도 높은 색은 인디고 한 가지로 제한하고(브랜드 일관성), 나머지는 슬레이트 그레이스케일로 여백/위계를 만든 뒤, 좋아요=로즈·성공=에메랄드처럼 **행동/상태별로만 포인트 컬러를 예외적으로 사용**하는 절제된 톤. 전반적으로 파스텔에 가까운 저채도 배경(`-50` 계열)과 고채도 포인트(`-500/-600` 계열)의 대비로 "밝고 차분한" 인상을 준다.

## 4. 간격 · 타이포그래피 톤 (Spacing & Type)

### 4.1 여백(Spacing) 스케일
- **화면 좌우 패딩**: `px-4`(16px)로 전 화면 통일
- **카드 내부 패딩**: `p-4`(16px)
- **헤더류 수직 패딩**: `py-2` ~ `py-3`(8~12px)
- **요소 간 간격(gap)**: 아이콘-텍스트는 `gap-1.5`(6px), 그룹 간은 `gap-2~gap-3`(8~12px) — 촘촘하지만 답답하지 않은 간격
- **카드 사이 간격**: `space-y-3.5`(14px)로 리스트 리듬 형성
- **카드 내부 섹션 간 여백**: `mb-1.5`(작성자 줄) → `mb-3`(제목) → `mb-3.5`(이미지/태그) 순으로 점진적으로 커짐 — 콘텐츠 밀도가 높은 상단은 촘촘히, 하단 액션 영역 전에는 여유를 둠

### 4.2 모서리 반경(Radius) 스케일
| 반경 | 사용처 |
|---|---|
| `rounded-full` | 아바타, 배지/뱃지 pill, 카테고리 칩, 액션 버튼, FAB |
| `rounded-xl` (12px) | 게시글 이미지, 링크 프리뷰 카드 |
| `rounded-2xl` (16px) | 게시글 카드 본체(가장 큰 표면 단위) |

→ **"카드는 크게 둥글게, 그 안의 요소는 한 단계 작게 둥글게, 태그/버튼류는 완전한 원/캡슐"** 이라는 3단 규칙이 전 화면에서 반복됨.

### 4.3 그림자(Elevation) 스케일
- `shadow-xs`/`shadow-2xs`: 헤더, 앱 컨테이너 등 미세한 표면 분리
- `shadow-sm`: 기본 게시글 카드
- `shadow-lg` + 색상 그림자(`shadow-indigo-300/50`): FAB처럼 가장 강조되는 플로팅 요소
→ 그림자 강도가 곧 시각적 우선순위(카드 < 헤더 < FAB)를 나타냄

### 4.4 타이포그래피 스케일
| 크기 | 용도 |
|---|---|
| `text-[10px]~text-[11px]` | 뱃지 라벨, 초미세 메타정보(이미지 카운터 등) |
| `text-xs` (12px) | 태그, 버튼 라벨, 타임스탬프, 카테고리 칩 |
| `text-sm` (14px) | 작성자 이름, 본문 요약 |
| `text-base` (16px) | 게시글 제목, 화면 타이틀 |
| `text-lg`/`text-xl` (18~20px) | 브랜드 로고, 상세 화면 제목 (다른 화면 기준) |

- **폰트**: Pretendard(한글 웹폰트, CDN) 우선 + 시스템 폰트 폴백 — 한글 가독성에 최적화된 기본값
- **굵기 위계**: `font-medium`(보조 텍스트) → `font-semibold`(이름/버튼) → `font-bold`(제목/강조) 3단계로 크기보다 굵기 변화로 위계를 자주 표현(작은 화면에서 크기 차이보다 굵기 차이가 스캔하기 쉬움)

### 4.5 종합 톤
전반적으로 **12~16px 기준의 촘촘한 모바일 타이포 스케일**, **완전 원형~16px 라운드의 부드러운 모서리**, **저채도 배경 위 인디고 포인트**가 결합되어 "친근하고 가벼운 커뮤니티 앱" 톤을 만든다. 여백은 넉넉하기보다 **효율적으로 압축된 모바일 밀도**에 가깝고, 상태 변화(좋아요/북마크/공유)는 색상+아이콘 채움의 즉각적 피드백으로 처리해 별도 애니메이션 없이도 반응성을 전달한다.
